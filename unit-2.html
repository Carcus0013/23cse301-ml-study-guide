Tree structure, entropy, information gain and ID3

Very importantIn your materialsDecision Tree.pptx · Regression.pdf

Question 1 of October 2025 (6 marks).

Concept

A decision tree is a supervised, non-parametric model shaped like a flowchart. Terminology from your slides: the root node holds the whole dataset; decision (internal) nodes test one attribute; branches are the test outcomes; leaf (terminal) nodes give the class; splitting divides a node; pruning removes unhelpful branches. A path from root to leaf reads as an if–then rule.

ID3 (Iterative Dichotomiser 3, Ross Quinlan) grows the tree top-down and greedily: at each node it splits on the attribute with the highest information gain, i.e. the one that makes the child nodes purest.

Entropy(S) = − Σᵢ pᵢ log₂ pᵢ (pᵢ = fraction of class i in S; 0·log 0 = 0)
Two classes: 0 when the node is pure, 1 when it is a 50/50 mix
Gain(S, A) = Entropy(S) − Σ_v (|S_v|/|S|) · Entropy(S_v)
S_v = the subset of S where attribute A takes value v. The weighted sum is the expected entropy left after splitting on A ("average information entropy" in your slides).

ID3 algorithm (your slides' steps)

  1. Compute the entropy of the current dataset S.
  2. For every attribute: compute the entropy of each of its values, take the weighted average, and compute the gain.
  3. Pick the attribute with the highest gain as the decision node; create one branch per value.
  4. Repeat on each branch with the remaining attributes, until a node is pure (entropy 0 → leaf), no attributes remain (leaf = majority class) or no samples remain.

Splitting criterion (Q1c): ID3 splits on the attribute with maximum information gain (equivalently, minimum weighted child entropy). Handy values: log₂(1/3) = −1.585, log₂(2/3) = −0.585, log₂(1/5) = −2.322, log₂(2/5) = −1.322, log₂(3/5) = −0.737, log₂(4/5) = −0.322. Entropy(2/5, 3/5) = 0.971, (1/3, 2/3) = 0.918, (1/4, 3/4) = 0.811, (9/14, 5/14) = 0.940.

  • Using natural log instead of log₂ (values then do not lie in 0–1 for two classes).

Gini index (CART) and gain ratio (C4.5)

ImportantIn your materialsDecision Tree.pptx · Regression.pdf

The most natural variation of Q1: the same table with Gini instead of entropy.

Concept

Three tree algorithms appear in your slides. ID3 uses information gain. C4.5 (Quinlan's successor) uses the gain ratio, which corrects information gain's bias toward attributes with many values (an ID-number attribute would get maximal gain while being useless). CART (Breiman) builds binary trees using the Gini index — "how often a randomly chosen element would be misclassified"; lower is purer.

Gini(S) = 1 − Σᵢ pᵢ² 0 = pure; 0.5 = 50/50 for two classes
Gini_split(A) = Σ_v (|S_v|/|S|) Gini(S_v) choose A with the lowest value (largest Gini gain)
SplitInfo(A) = − Σ_v (|S_v|/|S|) log₂(|S_v|/|S|)
GainRatio(A) = Gain(S, A) / SplitInfo(A)
ID3C4.5CART
CriterionInformation gainGain ratioGini index (classification), MSE (regression)
SplitsMulti-wayMulti-wayBinary only
AttributesCategoricalCategorical and continuous (thresholds), missing valuesCategorical and continuous
PruningNoneError-based post-pruningCost-complexity pruning

Quick revision

Gini = 1 − Σp²; pick the lowest weighted Gini. Gain ratio = Gain / SplitInfo (C4.5) to stop many-valued attributes winning. CART = binary + Gini; ID3 = gain; C4.5 = gain ratio.

Tree construction and pruning

ImportantPartialDecision Tree.pptx · Overfitting-and-Underfitting.pdf

Q1(d) asks for the final tree; pruning has only a definition in the notes.

Construction

Trees are grown by recursive partitioning (your slides): choose the best split, divide the data, recurse. Stopping (leaf) conditions: the node is pure; no attributes remain; too few samples; maximum depth reached; or the best gain is below a threshold. A leaf predicts the majority class (classification) or the mean value (regression).

Pruning

A fully grown tree overfits: deep branches fit noise. Pruning — "the opposite of splitting" — removes branches that do not help on unseen data.

  • Pre-pruning (early stopping): stop growing early — maximum depth, minimum samples per leaf, minimum gain. Cheap, but may stop before a useful split.
  • Post-pruning: grow the full tree, then cut back.
    • Reduced error pruning: replace a subtree by a leaf if that does not increase error on a validation set.
    • Cost-complexity (weakest-link) pruning (CART): minimise R_α(T) = R(T) + α·|leaves|.
R_α(T) = R(T) + α |T̃| R(T) = training error rate, |T̃| = number of leaves
Effective α of node t: α_t = [R(t) − R(T_t)] / (|T̃_t| − 1)
R(t) = error if t is turned into a leaf; R(T_t) = error of the subtree below t. The node with the smallest α_t is the weakest link and is pruned first; the best α is chosen by cross-validation.
Example 1 · BasicSource: practice problem

A subtree under node "Humidity" makes 7 errors on 40 validation samples. If the subtree is replaced by a leaf predicting the majority class, it makes 5 errors. Should it be pruned under reduced error pruning?

Subtree error = 7/40 = 17.5%; leaf error = 5/40 = 12.5% → leaf is not worse

Prune: the simpler leaf does better on unseen data, so the subtree was fitting noise.

Example 2 · IntermediateSource: practice problem on CART cost-complexity pruning (Breiman et al., Classification and Regression Trees, 1984, for the method)

Training error rates (as fractions of all 100 training samples): node t₁ as a leaf R = 0.10, its subtree R = 0.04 with 4 leaves; node t₂ as a leaf R = 0.06, its subtree R = 0.03 with 2 leaves. Which node is pruned first?

α(t₁) = (0.10 − 0.04)/(4 − 1) = 0.06/3 = 0.020 α(t₂) = (0.06 − 0.03)/(2 − 1) = 0.03/1 = 0.030 Smallest α → t₁ (weakest link)

Prune t₁ first (α = 0.02): its three extra leaves buy only 0.02 error reduction each.

α is the price paid in error per leaf removed; pruning the cheapest subtrees first gives the sequence of trees CART chooses from by cross-validation.

Example 3 · Exam levelSource: practice problem using PlayTennis gains (topic 23)

A pre-pruning rule says "do not split if the best information gain is below 0.05". (i) Would the root of PlayTennis be split? (ii) Inside the Sunny branch, would Humidity be used? (iii) Suppose a noisy dataset had a node with 3 samples where the best gain was 0.92 but each child held one sample. Should it be split? Compare pre- and post-pruning.

  1. Root: best gain Outlook 0.246 ≥ 0.05 → split.
  2. Sunny branch: Humidity gain 0.971 ≥ 0.05 → split (and its children are pure → leaves).
  3. Gain is high, but each child rests on a single sample — a split fitted to noise. A "minimum 5 samples per node" rule (pre-pruning) or validation-based post-pruning would stop or remove it.
  4. Pre-pruning is faster but short-sighted: a weak split may enable strong splits below it (the film example, topic 23, where Genre has gain 0.02 at the root but is perfect one level down). Post-pruning sees the whole tree first, so it is usually more accurate, at more computational cost.

Split at the root and in Sunny; do not trust the 3-sample split; post-pruning generally beats pre-pruning in accuracy, pre-pruning wins on speed.

Common mistakes
  • Pruning on the training set (training error never prefers the pruned tree).
  • Confusing pruning with feature selection.
Quick revision

Grow recursively until pure / no attributes / too few samples. Pruning fights overfitting. Pre-pruning: depth, min samples, min gain. Post-pruning: reduced error (validation), cost complexity α_t = (R(t) − R(T_t))/(leaves − 1).

Hyperplane, maximum marginal hyperplane, margin and support vectors

Very importantIn your materialsSVM ML.pdf · Classification.pdf

Question 3 of October 2025 — 8 marks, the largest question.

Concept

Many lines can separate two linearly separable classes. A Support Vector Machine picks the one with the widest gap to the nearest points of both classes — the maximum marginal hyperplane (MMH). A wide gap means a new point must move far before it is misclassified, so the MMH generalises best.

  • Hyperplane: the decision surface w·x + b = 0 — a line in 2-D, a plane in 3-D, a hyperplane in higher dimensions. w is perpendicular to it; b shifts it.
  • Margin boundaries: w·x + b = +1 and w·x + b = −1, parallel to the hyperplane and passing through the closest points.
  • Margin: the distance between the two boundaries = 2/‖w‖.
  • Support vectors (Q3a): the training points that lie exactly on the margin boundaries, i.e. those closest to the decision boundary. They alone determine the hyperplane: removing any other point changes nothing, moving a support vector moves the boundary (SVM ML.pdf: "If the support vectors move, the boundary changes").
Decision rule: ŷ = sign(w·x + b)
Hard-margin primal: minimise ½‖w‖² subject to yᵢ(w·xᵢ + b) ≥ 1 for all i
Distance of a point to the hyperplane: |w·x + b| / ‖w‖
Dual solution: w = Σ αᵢyᵢxᵢ , αᵢ > 0 only for support vectors; f(x) = sign(Σ αᵢyᵢ xᵢ·x + b)
Maximising 2/‖w‖ is the same as minimising ½‖w‖². The dual depends on the data only through dot products xᵢ·xⱼ — which is what makes the kernel trick (topic 29) possible.

Example 1 · BasicSource: practice problem

Example 2 · IntermediateSource: course material, SVM ML.pdf ("SVM Example: Find the Optimal Hyperplane")

Class A: (−0.5, 0.5), (0.5, 0.5), (1, 0.5), (1, 1), (1, −0.5), (2, 0). Class B: (4, 0), (4.5, 1), (4.5, 0.5), (5, −1), (5.5, 0). Find the support vectors, hyperplane, w, b and margin geometrically.

  1. Plot: A lies at x₁ ≤ 2, B at x₁ ≥ 4. The closest pair is (2, 0) in A and (4, 0) in B → these are the support vectors.
  2. The MMH is the perpendicular bisector of the closest pair: midway at x₁ = 3, vertical.
  3. So w = (w₁, 0). Conditions: w·(4,0) + b = +1 for B taken as +1 and w·(2,0) + b = −1 for A: 4w₁ + b = 1, 2w₁ + b = −1 → 2w₁ = 2 → w₁ = 1, b = −3.
  4. Margin = 2/‖w‖ = 2/1 = 2 (boundaries x₁ = 2 and x₁ = 4).

Support vectors (2, 0) and (4, 0); w = (1, 0), b = −3; hyperplane x₁ − 3 = 0 (x₁ = 3); margin 2.

Example 3 · Exam levelSource: practice problem

An SVM trained on six points gives w = (1, 1), b = −3. Points: (1, 1) −1, (0, 0) −1, (1, 0) −1, (2, 2) +1, (3, 3) +1, (2, 3) +1. (i) Check every point is correctly classified with margin ≥ 1. (ii) Identify the support vectors. (iii) Find the margin width. (iv) Write Q3(a)'s answer: what are support vectors?

yᵢ(w·xᵢ + b): (1,1): −1 × (1 + 1 − 3) = −1 × −1 = 1 ← on margin (0,0): −1 × (−3) = 3 (1,0): −1 × (−2) = 2 (2,2): +1 × (4 − 3) = 1 ← on margin (3,3): +1 × 3 = 3 (2,3): +1 × 2 = 2 All ≥ 1 ✓. margin = 2/‖w‖ = 2/√2 = 1.414

All correct; support vectors (1, 1) and (2, 2) (where yᵢ(w·xᵢ + b) = 1); margin 1.414.

Model answer for "What are support vectors?" (2 marks): Support vectors are the training samples closest to the decision boundary, lying on the margin hyperplanes w·x + b = ±1. They are the only points with non-zero Lagrange multipliers αᵢ, so they alone define the position and orientation of the maximum marginal hyperplane; removing other points leaves the classifier unchanged.

Common mistakes
  • Writing the margin as 1/‖w‖ — that is half the margin (distance from hyperplane to one boundary).
  • Calling every point near the boundary a support vector; only those with yᵢ(w·xᵢ + b) = 1.

SVM numerical: the augmented-vector (α) method

Very importantIn your materialsClassification.pdf (slides 137–143) · SVM ML.pdf

Q3(b) of October 2025 is worth 6 marks and expects this method.

The method in your notes

  1. Plot the points and choose the support vectors s₁, s₂, … (the closest points of the opposite classes).
  2. Augment each support vector with a 1 for the bias: s̃ = (x₁, x₂, 1).
  3. Write one equation per support vector: Σⱼ αⱼ (s̃ⱼ · s̃ᵢ) = yᵢ, with yᵢ = −1 for the negative class and +1 for the positive class.
  4. Solve the simultaneous equations for the α's.
  5. Compute w̃ = Σ αᵢ s̃ᵢ = (w₁, w₂, b). The hyperplane is w₁x₁ + w₂x₂ + b = 0.
  6. Check: every point should satisfy yᵢ(w·xᵢ + b) ≥ 1, with equality for the support vectors.
Σⱼ αⱼ (s̃ⱼ · s̃ᵢ) = yᵢ for each support vector i w̃ = Σ αᵢ s̃ᵢ
In this formulation α carries the class sign (negative for the negative class), so w̃ = Σαᵢs̃ᵢ already includes yᵢ.

Hard margin vs soft margin (C and slack ξ)

ImportantIn your materialsSVM ML.pdf (Step 4)

An easy theory variation of Q3, and the honest way to handle Q3's printed data.

Concept

A hard-margin SVM demands every training point be on the correct side with margin ≥ 1. It only works when the data are perfectly separable and is sensitive to a single outlier. A soft-margin SVM allows violations: each point gets a slack variable ξᵢ ≥ 0 measuring how far it falls short.

Soft margin: minimise ½‖w‖² + C Σ ξᵢ subject to yᵢ(w·xᵢ + b) ≥ 1 − ξᵢ, ξᵢ ≥ 0
ξᵢ = max(0, 1 − yᵢ(w·xᵢ + b)) (= hinge loss)
ξ = 0: correct and outside the margin. 0 < ξ ≤ 1: correct but inside the margin. ξ > 1: misclassified. C: large C punishes violations strongly (narrow margin, risk of overfitting); small C tolerates violations (wide margin, better generalization, risk of underfitting).
Hard marginSoft margin
AssumesPerfect separabilityOverlap / noise allowed
Constraintyᵢ(w·xᵢ+b) ≥ 1yᵢ(w·xᵢ+b) ≥ 1 − ξᵢ
OutliersOne outlier can wreck or prevent a solutionAbsorbed with a slack cost
HyperparameterNoneC
UseClean, theoretical dataReal-world data

ImportantIn your materialsClassification.pdf (slides 128–159) · SVM ML.pdf (Step 6)

Your notes include a non-linear α-method numerical; kernels are a common theory part.

Concept

When no straight line separates the classes (e.g. one class in a ring around the other), map the data with a non-linear function φ(x) into a higher-dimensional space where a linear separator exists. The kernel trick: the SVM's dual needs only dot products, so we never compute φ(x) explicitly — a kernel function K(x, z) = φ(x)·φ(z) gives the dot product directly in the original space.

Linear: K(x, z) = x·z
Polynomial: K(x, z) = (x·z + c)^d
RBF / Gaussian: K(x, z) = exp(−γ ‖x − z‖²) (γ = 1/(2σ²))
Sigmoid: K(x, z) = tanh(κ x·z + c)
Decision: f(x) = sign( Σ αᵢyᵢ K(xᵢ, x) + b )
KernelWhen (from your notes)
LinearMany features, text classification; fastest
PolynomialFeature interactions; less efficient and less used in practice
RBFDefault for non-linear data; very flexible (γ large → wiggly, overfits)
SigmoidBehaves like a neural network layer; occasional use

Bayes theorem: prior, likelihood, posterior, conditional independence

ImportantIn your materialsNaive_Bayes.pdf · Naive Bayes.pptx · Classification.pdf · MLP.pdf

Not tested in October 2025, but it has its own lecture and a full numerical, and HMMs build on it.

Concept

Conditional probability P(A | B) is the probability of A once we know B happened: P(A | B) = P(A ∩ B)/P(B). Bayes' theorem reverses a conditional: it updates a prior belief with evidence.

P(C | X) = P(X | C) · P(C) / P(X)
posterior = likelihood × prior / evidence
Evidence (total probability): P(X) = Σ_k P(X | C_k) P(C_k)
In your slides' words: P(C) — class prior; P(X) — predictor prior (evidence); P(X | C) — likelihood; P(C | X) — posterior. For classification, P(X) is the same for every class, so compare only P(X | C)P(C) (the MAP rule).
  • Independent events: P(A ∩ B) = P(A)P(B) (tossing a coin and rolling a die together, as in your notes).
  • Conditional independence of features given the class: P(x₁, x₂ | C) = P(x₁ | C) P(x₂ | C). This is the "naive" assumption of Naive Bayes (topic 31).

Gaussian, Multinomial and Bernoulli Naive Bayes; Laplace smoothing

ImportantIn your materialsNaive_Bayes.pdf · Naive Bayes.pptx · Classification.pdf

Your notes' Ham/Spam example with smoothing is exactly exam-shaped.

Concept

Naive Bayes classifies x = (x₁, …, x_d) by choosing the class with the largest posterior. Estimating P(x₁, …, x_d | C) jointly needs huge data, so it assumes the features are conditionally independent given the class:

ĉ = argmax_C P(C) · Πⱼ P(xⱼ | C)
Gaussian NB (continuous): P(xⱼ | C) = (1/√(2πσ²_{jC})) · exp(−(xⱼ − μ_{jC})² / (2σ²_{jC}))
Multinomial NB (word counts): P(w | C) = count(w, C) / total words in C
Bernoulli NB (binary present/absent): P(x | C) = Πⱼ pⱼ^xⱼ (1 − pⱼ)^(1−xⱼ)
Laplace (add-one) smoothing: P(w | C) = (count(w, C) + 1) / (total words in C + V)
V = vocabulary size. Without smoothing, one unseen word gives P = 0 and wipes out the whole product (the "zero-frequency problem"). In practice we add logarithms instead of multiplying tiny numbers.
AdvantagesDisadvantages
Very fast; needs little data; handles many features and multi-class problems; works well for text (spam, sentiment)The independence assumption is rarely true; probabilities are poorly calibrated; zero-frequency problem without smoothing; Gaussian NB assumes normal features

Markov property, states, initial and transition probabilities, sequence probability

Very importantIn your materialsMLP.pdf (slides 13–15)

Question 7(b) of October 2025 (4 marks).

Concept

A Markov model (Markov chain) describes a system that moves between a finite set of states over time according to probabilities. Its defining assumption is the Markov property ("memoryless"): the next state depends only on the current state, not on the history.

Markov property: P(q_{t+1} | q_t, q_{t−1}, …, q₁) = P(q_{t+1} | q_t)
Initial probabilities: πᵢ = P(q₁ = i), Σπᵢ = 1
Transition probability matrix (TPM): a_ij = P(q_{t+1} = j | q_t = i) (rows = from, columns = to; each row sums to 1)
Sequence probability: P(q₁, q₂, …, q_T) = π(q₁) · a(q₁,q₂) · a(q₂,q₃) ⋯ a(q_{T−1},q_T)
State distribution after n steps: p_{t+n} = p_t · Aⁿ ; stationary distribution: π* = π* A

Interactive simulator: Weather Markov chain in motion (needs JavaScript).

Example 1 · Basic — October 2025 Q7(b) (4 marks), full solutionSource: 23CSE301 end-semester paper, October 2025

States Sunny (S), Cloudy (C), Rainy (R) with π = (0.5, 0.3, 0.2) and TPM rows S: (0.6, 0.3, 0.1), C: (0.4, 0.4, 0.2), R: (0.3, 0.3, 0.4). Compute P(Sunny, Cloudy, Rainy, Rainy) and interpret.

FormulaP = π(S) · a(S→C) · a(C→R) · a(R→R), by the Markov property each factor depends only on the previous state.
π(S) = 0.5 a(S→C) = 0.3 (row S, column C) a(C→R) = 0.2 (row C, column R) a(R→R) = 0.4 (row R, column R) P = 0.5 × 0.3 × 0.2 × 0.4 = 0.012

P(S, C, R, R) = 0.012 (1.2%).

Interpretation: under this model only about 1.2% of four-day weather sequences follow exactly Sunny → Cloudy → Rainy → Rainy. The sequence is unlikely mainly because it starts with the rare Sunny→Cloudy and Cloudy→Rainy moves (0.3 and 0.2); once it rains, staying rainy (0.4) is the most likely rainy transition. For comparison, Sunny → Sunny → Sunny → Cloudy has probability 0.5 × 0.6 × 0.6 × 0.3 = 0.054.

Very importantIn your materialsMLP.pdf (slides 16–19)

Question 7(a) of October 2025 (2 marks).

Concept

A plain Markov model assumes we can see the states. Often we cannot: we see only observations that depend on a hidden state (your notes: "the underlying states are hidden, but we can observe outputs generated by those states"). A Hidden Markov Model has two linked sequences: a hidden state sequence that follows a Markov chain, and an observation sequence where each observation depends only on the current hidden state.

λ = (A, B, π)
A: transition matrix a_ij = P(q_{t+1} = j | q_t = i)
B: emission (observation) matrix b_j(o) = P(o_t = o | q_t = j)
π: initial state distribution πᵢ = P(q₁ = i)
Joint probability: P(O, Q) = π(q₁) b_{q₁}(o₁) · Π_{t=2..T} a(q_{t−1}, q_t) b_{q_t}(o_t)
Markov modelHidden Markov Model
StatesDirectly observedHidden
What we seeThe state sequenceObservations emitted by the states
Parametersπ, Aπ, A, B
Typical questionP(state sequence)P(observations); most likely hidden sequence; learn λ

Three classic problems (Rabiner): Evaluation — P(O | λ), solved by the Forward algorithm (topic 34). Decoding — most likely hidden sequence, Viterbi (topic 35). Learning — estimate λ from observations, Baum–Welch (topic 36).

Example 1 · BasicSource: course material, MLP.pdf slides 18–19 (umbrella example)

Hidden weather: Sunny, Rainy. π = (0.6, 0.4). Emissions: P(Umbrella | Sunny) = 0.1, P(Umbrella | Rainy) = 0.8. On the first day we observe an umbrella. What is the probability it was rainy?

P(U) = P(U|S)P(S) + P(U|R)P(R) = 0.1×0.6 + 0.8×0.4 = 0.06 + 0.32 = 0.38 P(R | U) = P(U|R)P(R)/P(U) = 0.32/0.38 = 0.842

P(Rainy | umbrella) = 0.842.

Seeing the umbrella raised the belief in rain from the prior 0.4 to 0.84 — an HMM is Bayes' theorem applied over time.

Example 3 · Exam level — October 2025 Q7(a) (2 marks)Source: 23CSE301 end-semester paper, October 2025

A speech recognition system is modelled with an HMM. Identify the hidden states and the observations and illustrate how they are related in recognising spoken words.

  1. Hidden states: the linguistic units being spoken — phonemes (or sub-phoneme states), which chain into words. They cannot be observed directly.
  2. Observations: the acoustic signal, cut into short frames (≈10 ms) and converted into feature vectors (e.g. MFCCs).
  3. Quick revision

HMM = hidden Markov chain + emissions. λ = (A, B, π). Problems: evaluation (Forward), decoding (Viterbi), learning (Baum–Welch). Applications: speech, POS tagging, bioinformatics.

Evaluation problem: the Forward algorithm

ImportantFrom outside sourcesNot in your folder · Jurafsky & Martin App. A

The natural next step after Q7; computable by hand on a two-state model.

Concept

Evaluation asks: how likely is an observation sequence O under model λ? Summing over every hidden path costs N^T terms (N states, T steps). The Forward algorithm uses dynamic programming: α_t(j) is the probability of seeing the first t observations and being in state j at time t. Each α reuses the previous column, so the cost drops to N²T.

Initialisation: α₁(j) = πⱼ · bⱼ(o₁)
Recursion: α_t(j) = [ Σᵢ α_{t−1}(i) · a_ij ] · bⱼ(o_t)
Termination: P(O | λ) = Σⱼ α_T(j)

Learning problem: the Baum–Welch algorithm

AdditionalFrom outside sourcesNot in your folder · Rabiner (1989) tutorial

Too long to compute fully in a two-hour exam; expect the idea and the steps, perhaps one γ value.

Concept

Learning asks: given only observation sequences, estimate λ = (A, B, π). The hidden states are missing data, so Baum–Welch applies the EM algorithm (topic 42) to HMMs: guess λ, compute expected state usage with the forward and backward variables (E-step), re-estimate λ from those expectations (M-step), repeat until P(O | λ) stops increasing. Each iteration never decreases the likelihood, but it can stop at a local maximum.

Backward: β_T(i) = 1; β_t(i) = Σⱼ a_ij bⱼ(o_{t+1}) β_{t+1}(j)
State posterior: γ_t(i) = α_t(i) β_t(i) / P(O)
Transition posterior: ξ_t(i, j) = α_t(i) a_ij bⱼ(o_{t+1}) β_{t+1}(j) / P(O)
M-step: π̂ᵢ = γ₁(i); â_ij = Σ_t ξ_t(i,j) / Σ_t γ_t(i) (t = 1..T−1); b̂ⱼ(k) = Σ_{t: o_t = k} γ_t(j) / Σ_t γ_t(j)

Reference for the formulas: L. R. Rabiner, "A Tutorial on Hidden Markov Models and Selected Applications in Speech Recognition", Proc. IEEE 77(2), 1989.

Example 1 · BasicSource: practice problem

Write the Baum–Welch algorithm as numbered steps and say how it relates to EM.

  1. Initialise λ = (A, B, π) (random or informed guess).
  2. E-step: run Forward (α) and Backward (β); compute γ_t(i) and ξ_t(i, j).
  3. M-step: re-estimate π, A, B with the ratios above (expected counts ÷ expected totals).
  4. Compute P(O | λ); if the increase is below a tolerance, stop, else go to step 2.

Baum–Welch = EM for HMMs: E-step = expected state/transition counts via forward–backward; M-step = normalised counts.

Perceptron: neuron model, step function, learning rule and logic gates

Very importantIn your materialsPerceptron_Neural_Networks.pdf

Question 8 of October 2025 (6 marks).

Concept

A biological neuron receives signals through dendrites, combines them in the cell body, and fires along the axon through synapses if the total exceeds a threshold — "all-or-none" behaviour (your notes). Rosenblatt's perceptron (1958) copies this: inputs xᵢ (dendrites) are multiplied by weights wᵢ (synapse strengths), summed with a bias b (the negative of the threshold), and passed through a step activation (firing).

Net input: y = Σᵢ wᵢxᵢ + b
Step activation: o = 1 if y ≥ 0, else 0 (Q8's convention)
Learning rule: wᵢ ← wᵢ + η (t − o) xᵢ , b ← b + η (t − o)
t = target, o = output, η = learning rate. If o = t nothing changes. If the perceptron said 0 but should say 1, weights of active inputs grow; if it said 1 but should say 0, they shrink. The perceptron convergence theorem: if the data are linearly separable, this rule finds a separating line in a finite number of updates.

Training algorithm

  1. Initialise weights and bias (zeros, small random values, or given).
  2. For each training pattern: compute y and o.

  4. One pass over all patterns = one epoch (iteration). Repeat until an epoch has no errors (convergence) or a maximum is reached.

Linear separability and the limitations of the perceptron (XOR)

ImportantIn your materialsPerceptron_Neural_Networks.pdf · MLP.pdf

The standard follow-up to Q8.

Concept

Two classes are linearly separable if one straight line (hyperplane) puts all of one class on one side and all of the other class on the other. A single perceptron's boundary w₁x₁ + w₂x₂ + b = 0 is a straight line, so it can learn only linearly separable problems. AND, OR, NAND and NOR are separable; XOR and XNOR are not. Minsky and Papert's 1969 book Perceptrons made this limitation famous and slowed neural-network research until multi-layer networks and backpropagation (1986).

Limitations of a single-layer perceptron (your MLP notes): cannot solve non-linearly separable problems; output is only binary (no probability); sensitive to input scaling; basic form handles only two classes; never converges on non-separable data (the weights cycle).

ImportantIn your materialsMLP.pdf · Perceptron_Neural_Networks.pdf

Architecture

An MLP has an input layer (one node per feature, no computation), one or more hidden layers of neurons with non-linear activations, and an output layer. It is fully connected and feed-forward: every node feeds every node of the next layer, with no loops.

Forward: z⁽¹⁾ = W⁽¹⁾x + b⁽¹⁾, h = σ(z⁽¹⁾), z⁽²⁾ = W⁽²⁾h + b⁽²⁾, ŷ = σ(z⁽²⁾)
Loss (one output): E = ½(t − ŷ)²
Output delta: δ_o = (ŷ − t) · ŷ(1 − ŷ) (sigmoid output)
Hidden delta: δ_hⱼ = (Σ_k δ_k w_jk) · hⱼ(1 − hⱼ)
Gradients: ∂E/∂w_jk = δ_k · (input to that weight); ∂E/∂b_k = δ_k
Gradient descent: w ← w − η ∂E/∂w
Backpropagation is the chain rule applied layer by layer from the output backward. MLP.pdf: forward pass → compute gradients → backpropagation → update weights; repeat for many epochs.

Maximum likelihood estimation: likelihood and log-likelihood

ImportantFrom outside sourcesNot in your folder

CO3 (parameter estimation or prediction) carried 6 marks in October 2025.

Concept

A model has unknown parameters θ (a coin's bias, a Gaussian's mean and variance). Having observed data D = (x₁, …, x_n), the likelihood L(θ) = P(D | θ) says how probable the data are for each value of θ. Maximum likelihood estimation (MLE) picks the θ that makes the observed data most probable.

Likelihood (i.i.d. data): L(θ) = Πᵢ P(xᵢ | θ)
Log-likelihood: ℓ(θ) = ln L(θ) = Σᵢ ln P(xᵢ | θ)
MLE: θ̂ = argmax_θ ℓ(θ) → solve dℓ/dθ = 0 (check it is a maximum)
Bernoulli (h heads in n): p̂ = h/n Gaussian: μ̂ = x̄, σ̂² = (1/n)Σ(xᵢ − x̄)² Poisson: λ̂ = x̄
Why logs? Products of many small numbers underflow, sums do not; logs turn products into sums that are easy to differentiate; ln is increasing, so the maximiser is unchanged. Likelihood is a function of θ for fixed data — not a probability distribution over θ.

Steps: (1) write L(θ); (2) take logs; (3) differentiate and set to zero; (4) solve for θ; (5) check the second derivative is negative. Least squares regression is MLE under Gaussian noise; logistic regression's cross-entropy is the negative log-likelihood.

Example 1 · BasicSource: practice problem

A coin gives 7 heads in 10 tosses. Write the likelihood, evaluate it at p = 0.5, 0.7 and 0.9, and derive the MLE.

p̂ = 0.7 = 7/10, the observed proportion of heads.

Prior belief about a coin's bias p is Beta(2, 2) (centred on 0.5). We observe 7 heads and 3 tails. Find the posterior, its mean, the MAP estimate, and compare with the MLE.

Posterior = Beta(2 + 7, 2 + 3) = Beta(9, 5) Posterior mean = 9/(9 + 5) = 9/14 = 0.643 MAP = (9 − 1)/(9 + 5 − 2) = 8/12 = 0.667 MLE = 7/10 = 0.700

Posterior Beta(9, 5); mean 0.643; MAP 0.667; MLE 0.700.

The prior acts like 2 imaginary heads and 2 tails, pulling the estimate toward 0.5.

Example 2 · IntermediateSource: practice problem

A coin is one of three types: p = 0.3, 0.5 or 0.8, with prior probabilities 0.25, 0.50, 0.25. Tosses give H, H, T. Find the posterior over types, the MAP type, the MLE type and P(next toss is H).

Likelihood p²(1 − p): 0.3 → 0.09×0.7 = 0.063; 0.5 → 0.125; 0.8 → 0.64×0.2 = 0.128 Prior × likelihood: 0.25×0.063 = 0.01575; 0.5×0.125 = 0.0625; 0.25×0.128 = 0.0320 Evidence = 0.01575 + 0.0625 + 0.032 = 0.11025 Posterior: 0.3 → 0.143; 0.5 → 0.567; 0.8 → 0.290 MLE type = 0.8 (largest likelihood 0.128); MAP type = 0.5 (largest posterior) P(H next) = 0.143×0.3 + 0.567×0.5 + 0.290×0.8 = 0.043 + 0.283 + 0.232 = 0.559

Posterior (0.143, 0.567, 0.290); MAP p = 0.5 but MLE p = 0.8; predictive P(H) = 0.559.

The data alone slightly favour 0.8, but the prior's preference for a fair coin outweighs three tosses. More data would shift the posterior.

Example 3 · Exam levelSource: practice problem

Exam scores are N(μ, σ² = 100). Prior on μ: N(50, 25). Four students score with mean x̄ = 60. Find the posterior of μ, compare with the MLE, and explain what happens as n grows.

Posterior precision = 1/τ² + n/σ² = 1/25 + 4/100 = 0.04 + 0.04 = 0.08 → τ_n² = 12.5 Posterior mean = 12.5 × (50/25 + 4×60/100) = 12.5 × (2 + 2.4) = 55 MLE = x̄ = 60

Posterior N(55, 12.5); MLE 60.

The posterior mean is a precision-weighted average of the prior mean (50) and the data mean (60); here they get equal weight (0.04 each). As n grows, n/σ² dominates, the posterior mean → x̄ and its variance → 0: Bayesian and MLE agree with enough data.

Common mistakes
  • Forgetting to normalise the posterior (divide by the evidence).
  • Confusing MAP (mode of the posterior) with the posterior mean.
Quick revision

Posterior ∝ likelihood × prior. MAP = argmax posterior. Beta(a,b) + h,k → Beta(a+h, b+k). Prior matters for small data; with large data Bayesian ≈ MLE.

Expectation–Maximization (EM): E-step, M-step, applications

ImportantFrom outside sourcesNot in your folder

Named in the syllabus; usually examined as the steps plus a small two-coin or mixture trace.

Concept

MLE is easy when all variables are observed. When some are hidden (latent) — which coin produced each set of tosses, which Gaussian produced each point, which HMM state produced each observation — the likelihood becomes hard to maximise directly. EM alternates two easy steps:

  1. Initialise parameters θ⁽⁰⁾.
  2. E-step (Expectation): using the current θ, compute the probability (responsibility) of each hidden value for each data point — a "soft" completion of the missing data.
  3. M-step (Maximization): re-estimate θ by MLE, treating the responsibilities as fractional counts.
  4. Repeat until the log-likelihood (or θ) stops changing.
Gaussian mixture E-step: r_ik = π_k N(xᵢ | μ_k, σ_k²) / Σ_j π_j N(xᵢ | μ_j, σ_j²)
M-step: N_k = Σᵢ r_ik, μ_k = Σᵢ r_ik xᵢ / N_k, σ_k² = Σᵢ r_ik (xᵢ − μ_k)² / N_k, π_k = N_k / n
N(x | μ, σ²) = (1/√(2πσ²)) exp(−(x − μ)²/(2σ²))
Properties: the likelihood never decreases from one iteration to the next; it converges to a local (not necessarily global) maximum, so restarts from different initial values help. Applications: Gaussian mixture clustering (soft K-means), Baum–Welch for HMMs (topic 36), missing-data imputation, topic models, image segmentation.

Interactive simulator: EM fits a Gaussian mixture (needs JavaScript).

Example 1 · BasicSource: practice problem

A two-component 1-D Gaussian mixture has μ₁ = 2, μ₂ = 5, σ₁² = σ₂² = 4, π₁ = π₂ = 0.5. Do the E-step for the point x = 3.

1/√(2π·4) = 1/√25.133 = 0.19947 N(3 | 2, 4) = 0.19947 × exp(−(1)²/8) = 0.19947 × 0.8825 = 0.17603 N(3 | 5, 4) = 0.19947 × exp(−(2)²/8) = 0.19947 × 0.6065 = 0.12098 Weighted: 0.5 × 0.17603 = 0.08802; 0.5 × 0.12098 = 0.06049; sum = 0.14851 r₁ = 0.08802/0.14851 = 0.593; r₂ = 0.407

x = 3 belongs 59.3% to component 1 and 40.7% to component 2.

Unlike K-means' hard assignment, EM splits the point between clusters according to probability.

Example 2 · IntermediateSource: Do & Batzoglou, "What is the expectation maximization algorithm?", Nature Biotechnology 26, 897–899 (2008), nature.com/articles/nbt1406; numbers also in the walkthrough at dev.to

Two coins A and B with unknown biases. Five sets of 10 tosses were made, each with one coin, but we do not know which: HTTTHHTHTH (5 H), HHHHTHHHHH (9 H), HTHHHHHTHH (8 H), HTHTTTHHTT (4 H), THHHTHHHTH (7 H). Start from θ_A = 0.6, θ_B = 0.5 and perform one EM iteration.

E-step for set 1 (5 H, 5 T): L_A = 0.6⁵ × 0.4⁵ = 0.000796; L_B = 0.5¹⁰ = 0.000977 w_A = 0.000796/(0.000796 + 0.000977) = 0.45, w_B = 0.55 expected counts: A gets 0.45×5 = 2.2 H, 2.2 T; B gets 2.8 H, 2.8 T Same for every set: Set H w_A w_B A: H T B: H T 1 5 0.45 0.55 2.2 2.2 2.8 2.8 2 9 0.80 0.20 7.2 0.8 1.8 0.2 3 8 0.73 0.27 5.9 1.5 2.1 0.5 4 4 0.35 0.65 1.4 2.1 2.6 3.9 5 7 0.65 0.35 4.5 1.9 2.5 1.1 Totals 21.3 8.6 11.7 8.4 M-step: θ_A = 21.3/(21.3 + 8.6) = 0.71 θ_B = 11.7/(11.7 + 8.4) = 0.58

After one iteration θ_A ≈ 0.71, θ_B ≈ 0.58. Repeating, EM converges to θ_A ≈ 0.80, θ_B ≈ 0.52 after about 10 iterations — as reported in the paper.

If we knew which coin made each set (B, A, A, B, A), plain MLE would give θ_A = 24/30 = 0.80 and θ_B = 9/20 = 0.45. EM recovers θ_A without that information.

Example 3 · Exam levelSource: practice problem (continues Example 1)

Data x = 1, 2, 3, 7, 8, 9 and the initial mixture of Example 1. Complete one full EM iteration (E-step for all points, then the M-step) and interpret the change.

E-step responsibilities r₁ (r₂ = 1 − r₁): x: 1 2 3 7 8 9 r₁: 0.867 0.755 0.593 0.068 0.033 0.016 M-step: N₁ = 0.867+0.755+0.593+0.068+0.033+0.016 = 2.331; N₂ = 6 − 2.331 = 3.669 μ₁ = (0.867·1 + 0.755·2 + 0.593·3 + 0.068·7 + 0.033·8 + 0.016·9)/2.331 = 5.035/2.331 = 2.160 μ₂ = Σ r₂x / N₂ = (30 − 5.035)/3.669 = 24.965/3.669 = 6.804 σ₁² = Σ r₁(x − 2.160)² / 2.331 = 2.170; σ₂² = 6.049 π₁ = 2.331/6 = 0.389; π₂ = 0.611

After one iteration: μ = (2.16, 6.80), σ² = (2.17, 6.05), π = (0.39, 0.61).

Component 2 moved from 5 toward the right-hand group {7, 8, 9}; further iterations pull μ₂ to about 8, μ₁ to about 2 and the weights to 0.5 each.

Common mistakes
  • Assigning each point wholly to one component in the E-step (that is K-means).
  • Forgetting to weight the M-step averages by the responsibilities.
  • Claiming EM always finds the global maximum.
Quick revision

EM handles hidden variables. E-step: responsibilities with current θ. M-step: weighted MLE. Repeat; likelihood never decreases; local optimum. Uses: GMMs, Baum–Welch, missing data.
