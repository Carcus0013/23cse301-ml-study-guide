What ML is and the types of machine learning

ImportantIn your materialsIntro_ML.pdf · entire_Machine Learning.pptx

Standard 2–4 mark definition and comparison question. It did not appear in October 2025, so it is due.

Concept

Traditional programming takes rules + data → answers: a programmer writes the rules. Machine learning reverses this: it takes data + answers → rules. The computer finds the rule (the model) itself from examples. Arthur Samuel (1959) defined it as the field that gives computers "the ability to learn without being explicitly programmed". Tom Mitchell's operational definition is the one examiners like: a program learns from experience E with respect to task T and performance measure P if its performance at T, measured by P, improves with E.

Your course notes give three reasons ML took off: voluminous data, computational power and powerful algorithms.

The four types

TypeWhat the data looks likeGoalAlgorithms in your syllabusEveryday example
SupervisedInputs X with known labels yLearn f: X → y to predict labels of new inputsKNN, linear/logistic regression, decision trees, SVM, Naive Bayes, perceptron/MLPSpam filter trained on emails marked spam/ham
UnsupervisedInputs X only, no labelsFind structure: groups, fewer dimensions, rulesK-means, hierarchical clustering, PCAGrouping customers by buying habits
Semi-supervisedFew labelled + many unlabelled examplesUse the unlabelled data to improve a supervised modelSelf-training, label propagationLabelling a few medical scans, using thousands of unlabelled ones
ReinforcementNo fixed dataset; an agent acts and receives rewardsLearn a policy that maximises long-term rewardQ-learning, value iterationA game-playing agent, a robot learning to walk

Supervised learning splits by the type of output: classification (output is a category: "disease"/"no disease") and regression (output is a real number: price, weight). Unsupervised learning, in your notes, has three jobs: clustering, dimensionality reduction and association rules (market-basket analysis).

Example 1 · BasicSource: practice problem

Classify each task as supervised (classification or regression), unsupervised, or reinforcement learning: (a) predicting tomorrow's temperature in °C from past readings; (b) grouping news articles into topics with no topic labels; (c) deciding whether a loan applicant will default, using past applicants whose outcome is known; (d) a program learning to play chess by playing against itself; (e) reducing 500 sensor readings to 10 summary features.

MethodAsk two questions. Are correct answers (labels) given? If yes, is the answer a number or a category? If there are no labels but there is a reward signal from acting, it is reinforcement learning.
  1. (a) Labels exist (past temperatures), and the output is a real number → supervised regression.
  2. (b) No labels; we want natural groups → unsupervised clustering.
  3. (c) Labels exist (default / no default), output is a category → supervised classification (binary).
  4. (d) No labelled moves; the program gets a win/loss reward after acting → reinforcement learning.
  5. (e) No labels; we want fewer variables → unsupervised dimensionality reduction (for example PCA).

(a) supervised regression · (b) unsupervised clustering · (c) supervised classification · (d) reinforcement · (e) unsupervised dimensionality reduction

Example 2 · IntermediateSource: practice problem, built on the T/P/E definition (Mitchell, Machine Learning, 1997, Ch. 1)

A hospital wants a system that flags chest X-rays showing pneumonia. It has 200 X-rays labelled by radiologists and 20,000 unlabelled X-rays. (i) State T, P and E. (ii) Which learning type fits best and why? (iii) Is it classification or regression?

  1. Task T: decide for each X-ray whether pneumonia is present.
  2. Performance P: for example recall on pneumonia cases (missing a sick patient is costly) together with precision.
  3. Experience E: the labelled and unlabelled X-rays.
  4. Only 1% of the images are labelled because labelling needs an expert. That is the exact situation your notes give for semi-supervised learning: "labelling instances is challenging or expensive". Train on the 200, use the model to pseudo-label confident unlabelled images, retrain.
  5. The output is a category (pneumonia / normal) → binary classification.

T = pneumonia detection, P = recall/precision, E = 200 labelled + 20,000 unlabelled X-rays; semi-supervised binary classification.

Interpretation: the type of learning is decided by the data you have, not by the problem alone. With 20,000 labelled X-rays this would be plain supervised learning.

Common mistakes

Quick revision

ML = learn rules from data. Supervised (labels; classification/regression) · Unsupervised (no labels; clustering, dimensionality reduction, association) · Semi-supervised (few labels) · Reinforcement (rewards). Mitchell: improve at T, measured by P, with experience E.

02

Features and feature representation

ImportantIn your materialsML_model_from_scratch.pdf · ML_pipeline.pptx · Intro_ML.pdf

Every numerical in this course starts from feature vectors, and scaling decides KNN, K-means and SVM answers.

Concept

A feature (attribute, independent variable) is one measurable property of an object. An object is represented as a feature vector x = (x₁, x₂, …, x_d), a point in d-dimensional space. Your notes call this the vector space model. Once objects are points, "similar objects" means "nearby points", and every distance-based algorithm can work.

A good feature takes different values for different classes (height separates cars from bikes). A bad feature takes the same value for every class (number of eyes of cats and dogs is always 2), so it carries no information. ML_pipeline.pptx makes exactly this point with legs and eyes.

Turning raw data into numbers

  • Data types (Stevens): nominal (no order: colour), ordinal (order: low/medium/high), interval (equal steps, no true zero: °C), ratio (true zero: weight).
  • Encoding categorical features: label encoding (0, 1, 2 — mainly for the target), ordinal encoding (keeps the order), one-hot encoding (one 0/1 column per category, for nominal features).
  • Scaling numeric features so no feature dominates a distance:
Min–max normalisation: x' = (x − min) / (max − min) → range [0, 1]
Standardisation (z-score): z = (x − μ) / σ → mean 0, std 1
μ = mean of the feature, σ = its standard deviation. Use min–max when you need a bounded range; use z-scores when the data are roughly Gaussian or have outliers that would squash min–max.

From your notes: distance-based methods (KNN, K-means, SVM) and gradient-descent methods need scaling; tree-based methods do not, because a tree splits one feature at a time.

Example 1 · BasicSource: course material, ML_model_from_scratch.pdf (vehicle example)

Vehicles are described by {#Wheels, Height, Weight, Colour}. Samples: (4, 6, 500, Red) Car, (4, 5.5, 600, Blue) Car, (2, 3, 200, Red) Bike, (2, 3.5, 150, Blue) Bike. Which features are good and which is bad for telling cars from bikes? Write the feature vector of the first sample with colour one-hot encoded over {Red, Blue, Yellow}.

  1. #Wheels: cars 4, bikes 2 → values differ by class → good.
  2. Height: cars 5.5–6, bikes 3–3.5 → no overlap → good.
  3. Weight: cars 500–600, bikes 150–200 → good.
  4. Colour: Red and Blue appear in both classes → tells nothing about the class → bad.
  5. One-hot colour: Red → (1, 0, 0). Feature vector: x = (4, 6, 500, 1, 0, 0).

Good: wheels, height, weight. Bad: colour. x₁ = (4, 6, 500, 1, 0, 0).

Example 2 · IntermediateSource: practice problem

Heights (cm) of five students: 150, 160, 170, 180, 190. Find the min–max value and the z-score (use population σ) for each.

Givenmin = 150, max = 190
Formulax' = (x − 150)/40; z = (x − μ)/σ
μ = (150+160+170+180+190)/5 = 850/5 = 170 σ² = [(−20)² + (−10)² + 0² + 10² + 20²] / 5 = 1000/5 = 200 → σ = √200 = 14.142 min–max: 0/40=0, 10/40=0.25, 20/40=0.5, 30/40=0.75, 40/40=1 z: −20/14.142=−1.414, −0.707, 0, 0.707, 1.414

Min–max: 0, 0.25, 0.5, 0.75, 1. z-scores: −1.414, −0.707, 0, 0.707, 1.414.

Both keep the order of the values; only the scale changes.

Example 3 · Exam levelSource: practice problem

Customers are described by (age in years, income in ₹). A = (25, 50000), B = (35, 52000), C = (26, 60000). Ages range 25–35 and incomes 50000–60000. Which customer is nearest to A by Euclidean distance (i) before scaling, (ii) after min–max scaling? Explain the difference.

(i) Raw: d(A,B) = √[(35−25)² + (52000−50000)²] = √(100 + 4,000,000) = 2000.02 d(A,C) = √[(26−25)² + (60000−50000)²] = √(1 + 100,000,000) = 10000.00 (ii) Scaled: age' = (age−25)/10, income' = (income−50000)/10000 A = (0, 0), B = (1, 0.2), C = (0.1, 1) d(A,B) = √(1² + 0.2²) = √1.04 = 1.020 d(A,C) = √(0.1² + 1²) = √1.01 = 1.005

Before scaling B is nearest (2000 vs 10000). After scaling C is nearest (1.005 vs 1.020).

Before scaling, income differences are thousands while age differences are tens, so income alone decides the distance and age is ignored. B is 10 years older than A; C is only 1 year older. Scaling lets both features count. This is why your lab note says "always scale before KNN".

Common mistakes
  • Using label encoding (0, 1, 2) for a nominal feature such as colour: it invents an order Red < Blue < Yellow.
  • Computing min, max, μ, σ on the whole dataset. Compute them on the training set only and reuse them for test data.
  • Forgetting to scale before a distance-based algorithm.
Quick revision

Feature = measurable property; object = feature vector. Good feature separates classes. Nominal → one-hot; ordinal → ordinal encoding. Min–max (x−min)/(max−min); z = (x−μ)/σ. Scale for KNN, K-means, SVM, gradient descent; not needed for trees.

03

Class boundaries and decision boundaries

ImportantPartialClassification.pdf · SVM ML.pdf

Needed to explain the effect of K in KNN and the SVM hyperplane; the notes only draw it in passing.

Concept

A classifier divides the feature space into regions, one per class. The decision boundary is the surface where the classifier is exactly undecided between two classes; points on one side get one label, points on the other side the other. A class boundary is the true separation between classes in the data; the decision boundary is the model's estimate of it.

  • Linear boundary: a straight line in 2D, a plane in 3D, a hyperplane in d dimensions: w·x + b = 0. Produced by the perceptron, logistic regression, linear SVM and LDA.
  • Non-linear boundary: curved. Produced by KNN, decision trees (axis-parallel staircase), kernel SVM and MLPs.
Linear classifier: predict class +1 if w·x + b ≥ 0, else class −1
Boundary: w₁x₁ + w₂x₂ + b = 0 ⇔ x₂ = −(w₁/w₂)x₁ − b/w₂
Logistic regression boundary: p = 0.5 ⇔ z = β₀ + β·x = 0
w is perpendicular (normal) to the boundary; b shifts it away from the origin.
Example 1 · BasicSource: practice problem

A linear classifier has w = (2, −1) and b = −4. Find its decision boundary and classify P = (3, 1) and Q = (1, 3).

Boundary: 2x₁ − x₂ − 4 = 0 → x₂ = 2x₁ − 4 P: 2(3) − 1 − 4 = 1 ≥ 0 → class +1 Q: 2(1) − 3 − 4 = −5 < 0 → class −1

Boundary x₂ = 2x₁ − 4 (slope 2, intercept −4). P → +1, Q → −1.

Example 2 · IntermediateSource: practice problem

A 1-nearest-neighbour classifier has two training points: A = (1, 1) of class + and B = (5, 3) of class −. Find the equation of its decision boundary.

Idea1-NN assigns each point to the nearer training point, so the boundary is the set of points equidistant from A and B: the perpendicular bisector of AB.
Midpoint M = ((1+5)/2, (1+3)/2) = (3, 2) Slope of AB = (3−1)/(5−1) = 0.5 → perpendicular slope = −1/0.5 = −2 Line through M: x₂ − 2 = −2(x₁ − 3) → 2x₁ + x₂ = 8 Check (3,2): 6 + 2 = 8 ✓

Decision boundary: 2x₁ + x₂ = 8. Points with 2x₁ + x₂ < 8 are class +.

With many training points, 1-NN's boundary is made of many such bisector pieces, which is why it looks jagged.

Example 3 · Exam levelSource: practice problem

A logistic regression model for admission uses exam score x₁ and interview score x₂: z = −10 + 0.1x₁ + 0.2x₂, P(admit) = σ(z). (i) Write the decision boundary at threshold 0.5. (ii) Classify a student with x₁ = 60, x₂ = 15. (iii) What interview score does a student with x₁ = 40 need?

(i) σ(z) = 0.5 ⇔ z = 0 → 0.1x₁ + 0.2x₂ = 10 ⇔ x₁ + 2x₂ = 100 (ii) z = −10 + 6 + 3 = −1 → σ(−1) = 1/(1+e¹) = 0.269 < 0.5 → not admitted (iii) 40 + 2x₂ ≥ 100 → x₂ ≥ 30

Boundary x₁ + 2x₂ = 100; the student is rejected (p = 0.269); an interview score of at least 30 is needed.

Logistic regression has a linear boundary even though its output curve is an S-shape: the S-curve only converts distance from the line into a probability.

Common mistakes
  • Thinking logistic regression has a curved boundary. Its boundary is linear in the features.
  • Forgetting that w points toward the positive class and is perpendicular to the boundary.
Quick revision

Decision boundary = where the classifier switches label. Linear: w·x + b = 0. 1-NN boundary = perpendicular bisectors. Logistic: z = 0. Larger K in KNN → smoother boundary.

04

Training, validation and testing; cross-validation

ImportantIn your materialsIntro_ML.pdf · Bias_variance.pptx

A common 2-mark comparison, plus the "why not test on training data" question.

Concept

A model is judged on how well it handles new data. So the available data is split into three disjoint parts:

SetUsed forChanges model weights?Typical share
TrainingFitting the model parameters (weights)Yes60–80%
ValidationChoosing hyperparameters (K, λ, depth), model selection, early stoppingNo10–20%
TestOne final, unbiased estimate of performance on unseen dataNo — used once at the very end10–20%

Why not train and test on the same data? A model can memorise the training examples and score perfectly without learning a general pattern (your notes: "memorizing examples rather than learning general patterns"). Only unseen data reveals that.

k-fold cross-validation

  1. Split the training data into k equal folds (commonly k = 5 or 10).
  2. For i = 1 … k: train on the other k − 1 folds, validate on fold i, record the score.
  3. Report the mean (and standard deviation) of the k scores. Repeat for each hyperparameter value and keep the best mean.
CV score = (1/k) Σᵢ scoreᵢ
Every example is used for validation exactly once, so an unlucky single split matters less (Bias_variance.pptx: "If you fear an unlucky split, try multiple splits"). Leave-one-out CV is the case k = n.
Example 1 · BasicSource: practice problem

A dataset has 1,000 samples. Split it 70 : 15 : 15. How many samples go to each set, and which set is used to choose K for KNN?

Train = 0.70 × 1000 = 700; Validation = 0.15 × 1000 = 150; Test = 0.15 × 1000 = 150

700 / 150 / 150. K is chosen on the validation set; the test set is touched only once, for the final report.

Example 2 · IntermediateSource: practice problem

5-fold cross-validation gives fold accuracies 0.82, 0.85, 0.80, 0.88, 0.85. Find the CV accuracy and its (population) standard deviation.

Mean = (0.82+0.85+0.80+0.88+0.85)/5 = 4.20/5 = 0.84 Deviations: −0.02, 0.01, −0.04, 0.04, 0.01 Squares: 0.0004, 0.0001, 0.0016, 0.0016, 0.0001 → sum 0.0038 σ = √(0.0038/5) = √0.00076 = 0.0276

CV accuracy = 0.84 ± 0.028.

The small spread says the model's performance does not depend much on which data it sees: low variance.

Example 3 · Exam levelSource: practice problem

KNN is tuned on a validation set. Results: K = 1: train 100%, val 78%; K = 5: train 91%, val 88%; K = 25: train 80%, val 79%. The chosen model then scores 87% on the test set. (i) Which K is chosen and why? (ii) Explain the K = 1 and K = 25 results. (iii) A student reports "best test accuracy over all K" instead. What is wrong?

  1. Choose the K with the best validation accuracy: K = 5 (88%).
  2. K = 1 memorises the training set (100% train) but generalises poorly (78% val): overfitting, high variance. K = 25 averages over too many neighbours, so even training accuracy drops (80%): underfitting, high bias.
  3. Picking K by test accuracy turns the test set into a second validation set. The reported number is then optimistically biased, because K was chosen to suit that particular test data. The test set must be used once, after all choices are made.

K = 5; K = 1 overfits, K = 25 underfits; choosing by test accuracy leaks test information and inflates the result.

Common mistakes
  • Tuning hyperparameters on the test set (data leakage).
  • Scaling or selecting features using all the data before splitting — another form of leakage.
  • Saying the validation set "trains" the model. It only guides choices.
Quick revision

Train → fit weights. Validation → pick hyperparameters/model. Test → final unbiased score, once. k-fold CV: average of k train/validate rounds; each sample validated once.

05

Generalization; underfitting, good fit and overfitting

Very importantIn your materialsOverfitting-and-Underfitting.pdf · Intro_ML.pdf · Bias_variance.pptx

Q2(a) of October 2025 asks how λ moves a model between underfitting and overfitting; you need this vocabulary to answer it.

Concept

Generalization is a model's ability to make accurate predictions on new data it was not trained on. Your notes use three students: A ignores the lectures (≈50% on every test — underfits), B memorises every solved question (98% on the class test, collapses on new questions — overfits), C learns the method (92% on both — good fit).

Example 1 · BasicSource: practice problem

Diagnose each model: M1 train error 25%, test error 27%; M2 train 2%, test 30%; M3 train 6%, test 8%.

  1. M1: both errors high and close → underfitting.
  2. M2: tiny training error, large test error, big gap → overfitting.
  3. M3: both low and close → good fit.

M1 underfits, M2 overfits, M3 fits well.

Example 2 · IntermediateSource: practice problem

Polynomials of degree 1, 3 and 9 are fitted to the same data. Mean squared errors: degree 1 — train 12.4, test 13.1; degree 3 — train 3.2, test 3.9; degree 9 — train 0.1, test 25.7. Which degree should be used? Explain each.

  1. Degree 1: errors high on both sets → the line cannot follow the curve → underfit.
  2. Degree 9: training error almost zero but test error is the worst → it has fitted the noise → overfit.
  3. Degree 3: lowest test error (3.9) and a small train–test gap (0.7) → best generalization.

Use degree 3: it has the lowest test error.

Always choose by validation/test error, never by training error — training error only ever goes down as complexity rises.

Example 3 · Exam level (6 marks)Source: practice problem in end-semester format

A decision tree reaches 100% training accuracy but 70% test accuracy. (i) Name the problem. (ii) Why are trees, KNN and other non-parametric models prone to it? (iii) Give four remedies and say which knob each turns.

  1. Overfitting (low bias, high variance): the 30-point gap is the signature.
  2. Non-parametric models have no fixed form; their complexity grows with the data. A tree can keep splitting until every leaf holds one training example, so it memorises noise (your Overfitting notes make exactly this point about trees and KNN).
  3. Remedies:
    • Pruning or a maximum depth — reduces tree complexity.
    • More training data — noise averages out.
    • Ensembles such as Random Forest — averaging many trees cuts variance.
    • Cross-validation to choose depth / minimum samples per leaf.

Overfitting; caused by unlimited model flexibility; fix with pruning/depth limits, more data, ensembles and cross-validated hyperparameters.

Common mistakes
  • Saying underfitting means "high variance". Underfitting = high bias.
  • Judging a model by training accuracy.
  • Thinking more complexity always helps.
Quick revision

Generalization = performance on unseen data. Underfit: high train + high test error (high bias). Overfit: low train, high test error (high variance). Good fit: both low and close. Fix overfitting with data, regularization, pruning, larger K, ensembles.

06

Loss functions and cost functions

ImportantPartialRegression.pdf · Gradient-Descent.pdf · Intro_ML.pdf · Logistic_regression_Assignment.docx

Regression, logistic regression and backpropagation all minimise one; no single lecture lists them together.

Concept

A loss function L(y, ŷ) measures how wrong one prediction ŷ is for one example with true value y. A cost function J (objective) is the average (sometimes sum) of the losses over the whole training set, possibly plus a regularization penalty. Training = finding the parameters that minimise J (Regression.pdf: "a cost function is a measure of how wrong the model is").

Squared error: L = (y − ŷ)² MSE J = (1/n) Σ (yᵢ − ŷᵢ)²
Absolute error: L = |y − ŷ| MAE J = (1/n) Σ |yᵢ − ŷᵢ|
Binary cross-entropy (log loss): L = −[ y ln p + (1−y) ln(1−p) ]
Hinge loss (SVM): L = max(0, 1 − y·f(x)), y ∈ {−1, +1}
0–1 loss (classification error): L = 0 if correct, 1 if wrong
Gradient-descent courses write J(θ₀, θ₁) = (1/2m) Σ (h(x) − y)²; the ½ only cancels the 2 when differentiating.
LossUsed byProperty

Cross-entropyLogistic regression, neural network classifiersPunishes confident wrong probabilities very heavily; convex for logistic regression

Why is cross-entropy used instead of MSE to train logistic regression? Use the prediction p = 0.01 for a true label y = 1 to compare the two losses.

MSE loss: (1 − 0.01)² = 0.9801 (can never exceed 1) Log loss: −ln(0.01) = 4.605 (grows without limit as p → 0)
  1. Penalty size: a confidently wrong prediction costs at most 1 under MSE but 4.6 (and → ∞) under log loss, so log loss pushes much harder to correct it.
  2. Convexity: MSE composed with the sigmoid gives a non-convex cost with flat regions and local minima; cross-entropy with the sigmoid is convex, so gradient descent reaches the global minimum.
  3. Probabilistic meaning: minimising cross-entropy is the same as maximising the likelihood of the labels (see topic 40, MLE).

Cross-entropy gives large gradients for confident errors, is convex for logistic regression, and equals maximum likelihood; MSE has none of these properties here.

Explainability in machine learning

AdditionalFrom outside sourcesNot in your folder

On the syllabus but with no lecture material, so expect at most a short definition or case question.

Concept

Explainability (explainable AI, XAI) is the ability to state, in human terms, why a model produced a given output. It matters when decisions affect people — loans, medical diagnosis, hiring — because users, regulators and developers must be able to check, contest and debug them.

  • Interpretable (white-box) models: the model itself is readable — linear/logistic regression (coefficients), decision trees (if–then rules), small rule lists.
  • Black-box models: deep networks, large ensembles, kernel SVMs — accurate but opaque. They need post-hoc explanation methods.
  • Global explanation: how the model behaves overall (feature importance). Local explanation: why it made one particular prediction.
  • Common post-hoc tools: feature importance, LIME (fits a simple linear model around one prediction), SHAP (Shapley values from game theory: each feature's fair share of the prediction), partial dependence plots, counterfactuals ("you would be approved if income were ₹5,000 higher").
Shapley value of feature i: φᵢ = Σ over subsets S not containing i of [ |S|!(n−|S|−1)!/n! ] · [ v(S∪{i}) − v(S) ]
v(S) = model output using only the features in S. Shapley values add up to v(all) − v(none). For n = 2 each feature's value is the average of its two marginal contributions.
Example 1 · BasicSource: practice problem

A linear credit-score model is: score = 300 + 2.0·(income in ₹1000s) − 1.5·(existing loans in ₹1000s) + 4·(years employed). For an applicant with income 50, loans 40, 5 years employed, explain the score feature by feature.

Baseline 300 income: 2.0 × 50 = +100 loans: −1.5 × 40 = −60 years: 4 × 5 = +20 score = 300 + 100 − 60 + 20 = 360

Score 360: income added 100, employment added 20, existing loans removed 60.

For a linear model the explanation is exact: coefficient × value is each feature's contribution. That is what "interpretable by design" means.

Example 2 · IntermediateSource: practice problem on Shapley values (Lundberg & Lee, "A Unified Approach to Interpreting Model Predictions", NeurIPS 2017, arXiv:1705.07874, for the method)

A model's output with no features is 50, with feature A alone 70, with feature B alone 60, and with both 90. Compute the Shapley values of A and B.

A's marginal contributions: added to {} → 70 − 50 = 20 ; added to {B} → 90 − 60 = 30 φ_A = (20 + 30)/2 = 25 B's marginal contributions: added to {} → 60 − 50 = 10 ; added to {A} → 90 − 70 = 20 φ_B = (10 + 20)/2 = 15 Check: φ_A + φ_B = 40 = 90 − 50 ✓

φ_A = 25, φ_B = 15.

A is credited with more of the 40-point rise above the baseline. SHAP does this for every feature of a black-box model.

Example 3 · Exam levelSource: practice problem

A bank must choose between a decision tree (accuracy 86%) and a deep neural network (accuracy 89%) for loan approval, and rejected applicants are entitled to a reason. Discuss the trade-off and recommend an approach.

  1. The tree is a white-box model: every rejection maps to a readable rule path ("income < 30k and loans > 50k → reject"), so reasons are exact and auditable.
  2. The network is 3 points more accurate but opaque; reasons would come from post-hoc tools (SHAP, LIME), which are approximations and can be unstable.
  3. Explainability also helps detect bias (topic 08) and debugging: a rule that rejects by pin code may be a proxy for a protected group.
  4. Recommendation: if the accuracy gain is small and decisions must be justified, use the tree (or a regularised logistic model); otherwise use the network and attach SHAP explanations plus human review of rejections.

Accuracy vs interpretability trade-off; for high-stakes, regulated decisions prefer an interpretable model or add local explanations and human oversight.

Common mistakes
  • Treating feature importance (global) as an explanation of one decision (local).
  • Claiming post-hoc explanations show exactly what the black box computes; they approximate it.
Quick revision

Explainability = human-understandable reasons. White-box (linear, tree) vs black-box (deep nets). Global vs local. Tools: feature importance, LIME, SHAP, counterfactuals. Needed for trust, regulation, debugging and fairness.

08

Algorithmic bias

AdditionalFrom outside sourcesNot in your folder

On the syllabus without lecture material; expect a definition plus one real case.

Concept

Algorithmic bias is systematic, unfair difference in a model's outcomes for different groups of people (by gender, race, age, region…). It is not the statistical "bias" of the bias–variance trade-off. Models learn patterns from data, so they also learn the unfairness in that data.

  • Historical bias: the world the data records was unfair (past hiring favoured men).
  • Representation / sampling bias: some groups are under-represented in training data.
  • Measurement bias: the label is a poor proxy (arrests used as a stand-in for crime).
  • Aggregation / evaluation bias: one model or one overall accuracy figure hides poor performance on a subgroup.
Disparate impact ratio = P(positive outcome | group B) / P(positive outcome | group A)
The US "four-fifths rule" flags a ratio below 0.8 as adverse impact.
Equal opportunity: TPR_A = TPR_B ; equalised odds: TPR and FPR equal across groups

Mitigation: collect representative data, audit metrics per group, remove or reweight biased features and samples, add fairness constraints, keep humans in the loop.

Example 1 · BasicSource: practice problem

A hiring model shortlists 60 of 100 male applicants and 30 of 100 female applicants. Compute the disparate impact ratio and apply the four-fifths rule.

Selection rate (male) = 60/100 = 0.60; (female) = 30/100 = 0.30 Ratio = 0.30 / 0.60 = 0.50 < 0.80

Ratio 0.50: the model shows adverse impact against female applicants.

Example 2 · IntermediateSource: ProPublica, "How We Analyzed the COMPAS Recidivism Algorithm" (2016), propublica.org

ProPublica's analysis of the COMPAS risk score reported these error rates: false positive rate (labelled high risk but did not re-offend) 44.85% for Black defendants and 23.45% for white defendants; false negative rate 27.99% for Black and 47.72% for white defendants. Interpret these numbers as a fairness problem.

FPR ratio = 44.85 / 23.45 = 1.91 FNR ratio (white / Black) = 47.72 / 27.99 = 1.70
  1. Black defendants who did not re-offend were wrongly labelled high-risk about 1.9 times as often as white defendants.
  2. White defendants who did re-offend were wrongly labelled low-risk about 1.7 times as often.
  3. So the errors are not shared equally: the model violates equalised odds, even though the developer argued its scores were equally calibrated for both groups. Both cannot hold at once when base rates differ — a well-known result in fairness research.

The model's mistakes harm one group (false alarms) and favour another (missed cases): an equalised-odds violation.

Example 3 · Exam levelSource: Buolamwini & Gebru, "Gender Shades", Proceedings of Machine Learning Research 81 (2018), proceedings.mlr.press

The Gender Shades study tested three commercial gender classifiers. Error rates reached up to 34.7% for darker-skinned women but at most 0.8% for lighter-skinned men, and two popular face benchmarks were 79.6% and 86.2% lighter-skinned. Identify the type(s) of bias, explain why overall accuracy hid the problem, and suggest remedies.

  1. Representation bias: training and benchmark data were dominated by lighter-skinned faces, so the models learned them best.
  2. Evaluation bias: a single overall accuracy is a weighted average dominated by the majority group, so a high overall score can coexist with a 34.7% subgroup error.
  3. Remedies: build balanced datasets (the authors created one balanced by gender and skin type); report accuracy for every intersectional subgroup; set minimum per-group performance before release.

Representation and evaluation bias; disaggregated (per-subgroup) evaluation and balanced data are the fixes.

Common mistakes
  • Confusing algorithmic bias with the bias term b or with statistical bias.
  • Thinking that removing the protected attribute removes bias: proxies such as pin code or name carry the same information.
Quick revision

Algorithmic bias = unfair outcomes across groups. Sources: historical, representation, measurement, aggregation/evaluation. Measures: disparate impact (four-fifths rule), equal opportunity, equalised odds. Cases: COMPAS, Gender Shades.

Data privacy and algorithmic privacy

AdditionalFrom outside sourcesNot in your folder

On the syllabus without lecture material; expect definitions and one technique.

Concept

Data privacy is about protecting personal information in the datasets used to train models: who may collect it, store it, and for what purpose. Algorithmic privacy is about what a trained model or its outputs reveal: a model can leak whether a person was in its training data (membership inference) or even reconstruct records.

  • Anonymisation is not enough: removing names still leaves quasi-identifiers (pin code, birth date, gender) that can be linked with other datasets.
  • k-anonymity: every record is identical to at least k − 1 others on the quasi-identifiers (achieved by generalising, e.g. exact age → age range).
  • Differential privacy (DP): add calibrated random noise so the output barely changes whether or not any one person's data is included. Privacy budget ε: smaller ε = more noise = more privacy.
  • Federated learning: train on users' devices and share only model updates, not raw data.
Laplace mechanism: output = true answer + Laplace(0, b), b = Δf / ε
Δf (sensitivity) = the most one person can change the answer (1 for a count). Laplace noise has variance 2b².
Example 1 · BasicSource: practice problem

A released table has quasi-identifiers (Pin code, Age, Gender) and a sensitive column (Disease). Rows: (641001, 21, F, Flu), (641002, 22, F, Diabetes), (641001, 23, F, Flu), (641112, 45, M, Asthma), (641115, 47, M, Flu), (641112, 49, M, Cancer). Generalise pin code to its first 4 digits and age to decades. What k-anonymity does the result satisfy?

After generalising: (6410**, 20–29, F) × 3 rows (6411**, 40–49, M) × 3 rows Each quasi-identifier combination appears 3 times → 3-anonymous

The generalised table is 3-anonymous: any individual hides among 3 identical records.

Before generalising, every row was unique, so knowing someone's pin code and age revealed their disease.

Example 2 · IntermediateSource: Narayanan & Shmatikov, "How To Break Anonymity of the Netflix Prize Dataset" (2006), arXiv:cs/0610105

Netflix released movie ratings with names replaced by random IDs for its recommendation competition. Explain how researchers re-identified users and what lesson it teaches about privacy in ML datasets.

  1. The researchers used public IMDb reviews as background knowledge.
  2. Matching a handful of (movie, rating, approximate date) triples between IMDb and the Netflix data was enough to single out a subscriber's full Netflix record, because individual rating histories are almost unique.
  3. Lesson: removing names is not anonymisation. High-dimensional behavioural data (ratings, locations, purchases) acts as a fingerprint. Protection needs techniques like differential privacy or not releasing the raw data.

Linkage with public data re-identified "anonymous" users; sparse high-dimensional data is inherently identifying.

Example 3 · Exam levelSource: practice problem on the Laplace mechanism (Dwork & Roth, The Algorithmic Foundations of Differential Privacy, 2014, for the method)

A hospital answers the query "how many patients have diabetes?" with differential privacy, ε = 0.5. (i) What is the sensitivity? (ii) Find the Laplace scale b, the noise variance and standard deviation. (iii) What happens with ε = 2?

(i) Adding/removing one patient changes a count by at most 1 → Δf = 1 (ii) b = Δf/ε = 1/0.5 = 2 ; variance = 2b² = 8 ; std = √8 = 2.83 (iii) b = 1/2 = 0.5 ; variance = 0.5 ; std = 0.71

Δf = 1; with ε = 0.5 the noise has std ≈ 2.83; with ε = 2 only ≈ 0.71 (less private, more accurate).

ε is the privacy–accuracy dial: smaller ε hides each individual better but makes the published count noisier.

Common mistakes
  • Equating "anonymised" with "private".
  • Thinking a larger ε means more privacy; it is the opposite.
Quick revision

Data privacy = protect personal data; algorithmic privacy = models must not leak it. Quasi-identifiers enable linkage attacks (Netflix). Defences: k-anonymity, differential privacy (noise scale Δf/ε), federated learning.

Curse of dimensionality

ImportantIn your materialsCurse_of_dimensionality.pptx · Dimensionality_Reduction.pdf

It has its own lecture deck and is a classic 4-mark theory question.

Concept

The curse of dimensionality (Richard Bellman's term) is the set of problems that appear when the number of features d grows: the volume of the feature space grows exponentially, so a fixed amount of data becomes extremely sparse. Your notes list the consequences:

  • Sparsity: to keep the same density of samples you need exponentially more data.
  • Distances lose meaning: in high dimensions the nearest and farthest neighbours are almost the same distance away, which breaks KNN and K-means.
  • Overfitting: more dimensions give a model more ways to fit noise.
  • Redundancy: many features are correlated and carry the same information.
  • Computational cost: training and storage grow with d.

Hughes phenomenon: with a fixed training-set size, accuracy first rises as features are added, then falls. Remedies are dimensionality reduction: feature selection (keep a subset) or feature extraction (PCA, LDA — build new, fewer features).

Cells in a grid with m bins per feature: m^d
Edge of a sub-cube holding fraction r of uniform data in a unit hypercube: e_d(r) = r^(1/d)
Fraction of a d-ball's volume in its outer shell of thickness ε: 1 − (1 − ε)^d

10, 100, 1,000 and 10¹⁰ cells; 5 × 10¹⁰ samples for d = 10.

Each new feature multiplies the data requirement by 10 — this exponential growth is the "curse".

In 10 dimensions a "neighbourhood" holding 10% of the data spans 79% of each feature's range — it is no longer local. Nearest-neighbour methods lose their meaning.

Example 3 · Exam levelSource: practice problem

(i) What fraction of a ball's volume lies in the outer 5% shell (ε = 0.05) for d = 2, 10 and 100? (ii) Use the result to explain why distance-based classifiers struggle in high dimensions and name two remedies.

  3. Remedies: reduce dimension with PCA or LDA; select the informative features; use models with regularization.

9.75%, 40.1%, 99.4%. Distances concentrate, so neighbourhoods stop being informative; reduce dimensionality.

Common mistakes
  • Saying "more features always improve accuracy" — the Hughes phenomenon says otherwise for fixed data size.
  • Calling PCA a feature selection method; it creates new features (extraction).
Quick revision

Volume grows as m^d → data becomes sparse; distances concentrate; overfitting rises; cost rises. Fix: feature selection, PCA, LDA, regularization, more data.

Principal Component Analysis (PCA)

ImportantIn your materialsDimensionality_Reduction.pdf

A by-hand covariance and eigenvalue numerical is the most likely new Unit I question.

Concept

PCA is an unsupervised feature-extraction method. It rotates the coordinate axes so that the first new axis (principal component 1) points in the direction of greatest variance in the data, the second in the direction of greatest remaining variance perpendicular to the first, and so on. Keeping only the first k components reduces d features to k while keeping most of the information (variance). Your notes frame variance as "signal" and the small remaining directions as "noise".

The five steps (as in your notes)

  1. Standardise (or at least mean-centre) each feature.
  2. Covariance matrix C (d × d): Cjk = Σ (xij − x̄j)(xik − x̄k) / (n − 1).
  3. Eigen-decomposition: solve det(C − λI) = 0 for eigenvalues λ, then (C − λI)v = 0 for eigenvectors v.
  4. Feature vector: sort eigenvectors by eigenvalue (largest first) and keep the top k.
  5. Recast the data: project each centred point: score = vᵀ(x − x̄).
2×2 covariance C = [a b; b c]: λ = (a+c)/2 ± √[((a−c)/2)² + b²]
Eigenvector for λ: (b, λ − a) then divide by its length
Proportion of variance explained by PCᵢ = λᵢ / Σλ
Eigenvalue = variance along that component; eigenvector = its direction. Components are uncorrelated and orthogonal. Disadvantages: components are less interpretable, PCA is linear and ignores class labels.

Interactive simulator: Rotate the projection axis (needs JavaScript).

Example 1 · BasicSource: practice problem

det(C − λI) = (2−λ)² − 1 = 0 → 2 − λ = ±1 → λ₁ = 3, λ₂ = 1 λ₁ = 3: (C − 3I)v = [−1 1; 1 −1]v = 0 → v₁ = (1, 1)/√2 = (0.707, 0.707) λ₂ = 1: (C − I)v = [1 1; 1 1]v = 0 → v₂ = (1, −1)/√2 = (0.707, −0.707) Variance explained by PC1 = 3/(3+1) = 0.75

The features rise together (positive covariance), so the main direction is the 45° diagonal.

Linear Discriminant Analysis (LDA)

ImportantIn your materialsLDA-1.pdf (handwritten) · Dimensionality_Reduction.pdf

Concept

LDA (Fisher's linear discriminant) is a supervised projection. Like PCA it projects each point onto a direction w (y = wᵀx), but it chooses w to separate the classes: "different classes as far apart as possible while samples of the same class remain as close as possible" (LDA-1.pdf). It maximises the Fisher criterion.

Class means: μ₁ = (1/N₁) Σ_{x∈C₁} x , μ₂ = (1/N₂) Σ_{x∈C₂} x
Within-class scatter: S_W = S₁ + S₂ , Sᵢ = Σ_{x∈Cᵢ} (x − μᵢ)(x − μᵢ)ᵀ
Between-class scatter (2 classes): S_B = (μ₁ − μ₂)(μ₁ − μ₂)ᵀ
Fisher criterion: J(w) = (m₁ − m₂)² / (s₁² + s₂²) = wᵀS_B w / wᵀS_W w
Optimal direction (2 classes): w ∝ S_W⁻¹ (μ₁ − μ₂)
2×2 inverse: [a b; c d]⁻¹ = (1/(ad − bc)) [d −b; −c a]
General case: solve S_W⁻¹S_B w = λw; the eigenvector with the largest λ is the first discriminant. With C classes there are at most C − 1 useful directions. Assumptions (Dimensionality_Reduction.pdf): Gaussian classes, a shared covariance matrix, linear separability.

Feature selection: forward, backward and bidirectional

ImportantPartialDimensionality_Reduction.pdf

Named in the syllabus; the notes give one slide each, so expect theory with a short trace.

Concept

Feature selection keeps a subset of the original features; feature extraction (PCA, LDA) builds new features as combinations. Selection keeps features interpretable (you still know what "age" means).

  • Filter methods: score each feature on its own (correlation with the target, chi-square, information gain, variance threshold) — fast, model-independent.
  • Wrapper methods: try subsets with an actual model and keep the subset with the best validation score — slower, usually better. Sequential selection is a wrapper.
  • Embedded methods: selection happens during training — LASSO drives weights to 0; trees report importance.

Sequential algorithms

  1. Sequential Forward Selection (SFS): start with the empty set; at each step add the single feature that most improves the score J; stop when no addition improves J (or at k features).
  2. Sequential Backward Selection (SBS): start with all features; at each step remove the feature whose removal gives the best J; stop when every removal makes J worse (or at k features).
  3. Bidirectional search: run SFS from the empty set and SBS from the full set at the same time. Features added by SFS may not be removed by SBS, and features removed by SBS may not be added by SFS, so both converge to the same subset.

Search sizes: exhaustive search tests 2^d − 1 subsets; SFS/SBS test at most d(d+1)/2. SFS cannot remove a feature that later becomes useless (the "nesting" problem); floating variants fix this.

KNN algorithm, choosing K and the effect of K

Very importantIn your materialsClassification.pdf · KNN_classifier.pptx

Q2(b) of October 2025 tests KNN directly.

Concept

K-Nearest Neighbours is a supervised, non-parametric, instance-based (lazy) learner. It builds no model during training — it simply stores the training data. To classify a new point it finds the K closest stored points and takes a majority vote of their labels (for regression, the mean of their values). Its assumption: similar things exist close together.

Algorithm

  1. Choose K and a distance metric (Euclidean by default); scale the features.
  2. Compute the distance from the query point to every training point.
  3. Sort the distances in ascending order and take the K nearest.
  4. Classification: majority vote (optionally weighted by 1/d). Regression: average of the K values.

Choosing K

  • Small K (e.g. 1): boundary follows every point, sensitive to noise → overfitting, high variance.
  • Large K: boundary becomes smooth, minority patterns are outvoted → underfitting, high bias. At K = n every point gets the majority class.
  • Choose K by validation / cross-validation; use an odd K for two classes to avoid ties; a common rule of thumb is K ≈ √n.
AdvantagesDisadvantages
No training time; simple; naturally multi-class; adapts to any boundary shapeSlow prediction (distance to every point); needs scaling; hurt by irrelevant features and the curse of dimensionality; sensitive to imbalance and outliers (your notes recommend removing outliers)

Very importantIn your materialsClassification.pdf

Concept

A distance metric turns "similar" into a number. For x = (x₁ … x_d) and y = (y₁ … y_d):

Euclidean (L2): d = √[ Σ (xᵢ − yᵢ)² ] straight-line ("as the crow flies")

Minkowski (Lp): d = ( Σ |xᵢ − yᵢ|^p )^(1/p) p = 1 → Manhattan, p = 2 → Euclidean
Chebyshev (L∞): d = maxᵢ |xᵢ − yᵢ| limit p → ∞
Hamming: number of positions that differ (categorical / binary data)

EuclideanSquares differences, so one large difference dominatesLow-dimensional continuous data where straight-line distance is meaningful (physical positions)
ManhattanAdds absolute differences; less sensitive to one outlying featureGrid movement (city streets, warehouse aisles), high-dimensional or sparse data, features with outliers

Example 3 · Exam level — October 2025 Q2(b), 4 marksSource: 23CSE301 end-semester paper, October 2025

In KNN, explain how the choice of distance metric (e.g. Euclidean or Manhattan) can influence the classification result. Give an example scenario in 1–2 lines where one metric may be more suitable.

  1. Why the metric matters: KNN's only notion of similarity is the distance. A different metric produces a different ranking of neighbours, so the K nearest points — and therefore the majority vote — can change (Example 2 above shows one point flip from Red to Blue).
  2. Euclidean = √Σ(xᵢ − yᵢ)². Squaring magnifies large differences, so one feature with a big gap or an outlier can dominate. Neighbourhoods are circles (spheres).
  3. Manhattan = Σ|xᵢ − yᵢ|. Every unit of difference counts equally; it is more robust to outliers and behaves better in high dimensions. Neighbourhoods are diamonds.
  4. Both need scaled features; otherwise the feature with the largest range dominates either metric.
  5. Scenario: a delivery app recommending the nearest warehouse in a city with a grid road layout should use Manhattan, because vehicles travel along perpendicular streets; for a drone delivery, straight-line Euclidean distance is the true travel distance.

The metric decides who the neighbours are, so it can change the predicted class. Euclidean suits continuous, low-dimensional, straight-line problems; Manhattan suits grid-like movement, high-dimensional or outlier-prone data.

Linear regression: least squares and gradient descent

ImportantIn your materialsRegression.pdf · Gradient-Descent.pdf · gradient_descent_4_epochs.pdf

Two solved gradient-descent handouts exist in your folder; a numerical is likely in a future paper.

Concept

Linear regression models a continuous target as a straight-line function of the inputs: ŷ = β₀ + β₁x (simple) or ŷ = β₀ + β₁x₁ + … + β_dx_d (multiple). β₀ is the intercept (bias), β₁ the slope: the change in ŷ for a one-unit rise in x. The "best" line minimises the sum of squared residuals (errors) eᵢ = yᵢ − ŷᵢ.

Ordinary least squares (analytical): β₁ = Σ(xᵢ − x̄)(yᵢ − ȳ) / Σ(xᵢ − x̄)² , β₀ = ȳ − β₁x̄
Cost: J(θ₀, θ₁) = (1/2m) Σ (h(xᵢ) − yᵢ)² , h(x) = θ₀ + θ₁x
Gradient descent (numerical): θ₀ := θ₀ − α·(1/m) Σ (h(xᵢ) − yᵢ)
θ₁ := θ₁ − α·(1/m) Σ (h(xᵢ) − yᵢ)·xᵢ
Goodness of fit: R² = 1 − SSE/SST , SSE = Σ(yᵢ − ŷᵢ)² , SST = Σ(yᵢ − ȳ)²
α = learning rate (step size). Too large → overshoots and may diverge; too small → very slow. The OLS line always passes through (x̄, ȳ). Assumptions: linear relationship, independent errors with constant variance, little multicollinearity.

Very importantPartialRegression.pdf · Logistic_regression_Assignment.docx

Concept

Logistic regression is a classification algorithm despite its name. A straight line can output any number, but a probability must lie in [0, 1]. Your notes' fix: model the log of the odds as a straight line, then convert back with the sigmoid.

Odds = p / (1 − p) (range 0 to ∞)
Log-odds (logit) = ln[p/(1 − p)] = z = β₀ + β₁x₁ + … + β_dx_d (range −∞ to ∞)
Sigmoid: p = σ(z) = 1 / (1 + e^(−z)) (range 0 to 1, σ(0) = 0.5)
Odds ratio for a 1-unit rise in x_j: OR = e^(β_j) so β_j = ln(OR)
2×2 table: OR = (odds in group 1)/(odds in group 0) = (a/b)/(c/d) = ad/bc
Loss: cross-entropy −[y ln p + (1−y) ln(1−p)]; predict 1 if p ≥ 0.5 (z ≥ 0)

Concept

An overfitted model typically has very large coefficients that bend it toward the noise. Ridge (L2): J = Σ (yᵢ − ŷᵢ)² + λ Σ βⱼ²

Example 3 · Exam level — October 2025 Q2(a), 2 marksSource: 23CSE301 end-semester paper, October 2025

In the context of regularization, explain how increasing the value of the regularization parameter λ affects the bias–variance trade-off.

  1. Increasing λ increases the penalty on large coefficients, so the weights shrink toward zero (and some become exactly zero in LASSO). The model becomes simpler and less flexible.
  2. A simpler model fits the training data less closely, so bias increases; it also changes less from one training sample to another, so variance decreases.
  3. Small λ → low bias, high variance (risk of overfitting). Very large λ → high bias, low variance (underfitting: ŷ ≈ ȳ). The best λ, found by cross-validation, minimises total test error = bias² + variance + noise.

Raising λ shrinks the coefficients: bias ↑, variance ↓. Too little λ overfits, too much underfits; choose λ by cross-validation.

Common mistakes
  • Saying "increasing λ increases variance" — it is the reverse.
  • Claiming Ridge does feature selection.
  • Penalising the intercept.
Quick revision

Ridge: +λΣβ², shrinks. LASSO: +λΣ|β|, shrinks and zeros (selection). λ↑ ⇒ bias↑ variance↓. λ = 0 is OLS. Choose λ by CV.

Bias–variance trade-off

Very importantIn your materialsBias_variance.pptx · Intro_ML.pdf

Question 2(a) of October 2025 asks for it by name.

Concept

Imagine training the same kind of model on many different training sets drawn from the same population and predicting at one point x₀.

  • Bias = how far the average prediction is from the truth. It comes from wrong or over-simple assumptions (Bias_variance.pptx: "error due to inaccurate assumptions/simplifications").
  • Variance = how much the predictions scatter from one training set to another — sensitivity to the particular sample.
  • Irreducible error σ² = noise in the data that no model can remove.
E[(y − f̂(x₀))²] = Bias² + Variance + σ²
Bias = E[f̂(x₀)] − f(x₀) , Variance = E[(f̂(x₀) − E[f̂(x₀)])²]

Regularization λSmall λLarge λ

Polynomial degreeHighLow
EnsemblesBoosting lowers biasBagging lowers variance

Your notes: to reduce variance choose a simpler classifier, cross-validate parameters, or get more training data.

Example 3 · Exam level (8 marks)Source: derivation as in Bias_variance.pptx notes and Bishop, Pattern Recognition and Machine Learning §3.2

Derive E[(y − f̂)²] = bias² + variance + σ², where y = f + ε, E[ε] = 0, Var(ε) = σ², and ε is independent of f̂. Then explain the trade-off.

Write f̄ = E[f̂]. y − f̂ = (f − f̄) + (f̄ − f̂) + ε Square and take expectations: E[(y − f̂)²] = (f − f̄)² + E[(f̄ − f̂)²] + E[ε²] + 2(f − f̄)E[f̄ − f̂] + 2(f − f̄)E[ε] + 2E[(f̄ − f̂)ε] Cross terms: E[f̄ − f̂] = 0; E[ε] = 0; E[(f̄ − f̂)ε] = E[f̄ − f̂]·E[ε] = 0 (independence) ⇒ E[(y − f̂)²] = (f − f̄)² + E[(f̂ − f̄)²] + σ² = Bias² + Variance + Noise
  1. Flexible models can match f closely (small bias) but react to every quirk of the sample (large variance); rigid models do the opposite.
  2. Since the sum is what we pay, the best model balances the two; noise σ² sets a floor no model can beat.
  3. Tools that move the balance: regularization λ, K in KNN, depth/pruning, bagging (↓ variance), boosting (↓ bias), more data (↓ variance).

Expected squared error = bias² + variance + irreducible noise; minimise the sum, not either term alone.

Common mistakes
  • Writing "bias + variance" without squaring the bias.
  • Thinking the noise term can be reduced by a better model.
  • Confusing this statistical bias with algorithmic (fairness) bias or the bias weight b.
Quick revision

Error = bias² + variance + σ². Simple models: high bias. Complex models: high variance. Underfit ↔ bias, overfit ↔ variance. Regularize, prune, tune K, bag, or add data to cut variance.

ImportantIn your materialsIntro_ML.pdf (slides 133–158)

Easy to set as a numerical and not tested in October 2025, so a good candidate for the next paper.

Concept

A confusion matrix tabulates predictions against actual labels. For a binary problem with a "positive" class:

Actual positiveActual negative
Predicted positiveTP (true positive)FP (false positive, Type I error)
Predicted negativeFN (false negative, Type II error)TN (true negative)
Accuracy = (TP + TN) / (TP + TN + FP + FN)
Precision = TP / (TP + FP) "of the predicted positives, how many are right?"
Recall (sensitivity, TPR) = TP / (TP + FN) "of the actual positives, how many did we find?"
Specificity (TNR) = TN / (TN + FP) FPR = FP / (FP + TN) = 1 − specificity
F1 = 2·P·R / (P + R) (harmonic mean of precision and recall)
The harmonic mean punishes imbalance: P = 1, R = 0.1 gives F1 = 0.18, while the arithmetic mean would be 0.55. Multi-class: compute P and R per class, then average (macro) or weight by class size.

ROC curve and AUC

ImportantIn your materialsIntro_ML.pdf (slides 143–144)

Usually paired with the confusion matrix as a theory or short numerical part.

Concept

Most classifiers output a score or probability; a threshold turns it into a class. Each threshold gives one (FPR, TPR) pair. The ROC curve (receiver operating characteristic) plots TPR (recall) against FPR for all thresholds. A perfect classifier passes through (0, 1); a random one lies on the diagonal.

The AUC (area under the ROC curve) summarises the curve in one number: it is the probability that a randomly chosen positive is scored higher than a randomly chosen negative (your notes). Your notes' grading scale: 0.9–1 excellent, 0.8–0.9 good, 0.7–0.8 fair, 0.6–0.7 poor, 0.5–0.6 fail.

TPR = TP/(TP + FN) , FPR = FP/(FP + TN)
AUC = (# positive–negative pairs where the positive scores higher) / (P × N) (ties count ½)
Trapezoid rule: AUC = Σ (FPRᵢ₊₁ − FPRᵢ)(TPRᵢ₊₁ + TPRᵢ)/2
ROC/AUC is threshold-independent and insensitive to class balance; it measures ranking quality, not calibration (your notes point to log loss for that).

Regression metrics: RMSE, MAPE, R² (with MAE and MSE)

ImportantIn your materialsIntro_ML.pdf (slides 159–165)

Named in the syllabus; a quick numerical from a small table.

Concept and formulas

MAE = (1/n) Σ |yᵢ − ŷᵢ| average size of the error, same units as y
MSE = (1/n) Σ (yᵢ − ŷᵢ)² squared units; large errors dominate
RMSE = √MSE back in y's units; penalises large errors
MAPE = (100%/n) Σ |yᵢ − ŷᵢ| / |yᵢ| percentage error; scale-free
R² = 1 − SSE/SST = 1 − Σ(yᵢ − ŷᵢ)² / Σ(yᵢ − ȳ)² share of variance explained
Adjusted R² = 1 − (1 − R²)(n − 1)/(n − k − 1) k = number of predictors
RMSE ≥ MAE always; a big gap means a few large errors. MAPE breaks when some yᵢ = 0 and is asymmetric. R² = 1 is perfect, 0 means "no better than predicting ȳ", negative means worse than ȳ. R² never falls when you add a predictor; adjusted R² does if the predictor is useless.

True values 3, 5, 8, 4. Model A predicts 2.5, 5.5, 7, 5; Model B predicts 3, 5, 8, 8. Compute MAE and RMSE for both, say which each metric prefers and why. When would you report MAPE, and when not?

A errors: 0.5, −0.5, 1, −1 → MAE = 3/4 = 0.75; MSE = (0.25+0.25+1+1)/4 = 0.625 → RMSE = 0.791 B errors: 0, 0, 0, −4 → MAE = 4/4 = 1.00; MSE = 16/4 = 4 → RMSE = 2.000
  1. Both metrics prefer A here, but RMSE separates them far more (0.79 vs 2.00) than MAE (0.75 vs 1.00), because B's one large error is squared.
  2. Use RMSE when large errors are especially harmful (e.g. stock forecasts); MAE when all errors cost the same and outliers should not dominate.
  3. MAPE is good for explaining errors in business terms ("off by 7% on average") when all actual values are well above zero; avoid it when actuals can be 0 or near 0 (division blows up).

A: MAE 0.75, RMSE 0.79. B: MAE 1.00, RMSE 2.00. RMSE punishes B's single big miss hardest.

Common mistakes
  • Forgetting the square root in RMSE.
  • Dividing MAPE by the prediction instead of the actual value.
  • Reporting R² on training data as evidence of generalization.
Quick revision

MAE = mean |e|; MSE = mean e²; RMSE = √MSE; MAPE = mean |e/y| × 100%; R² = 1 − SSE/SST; adjusted R² penalises extra predictors.
